# Interface Control Document (ICD): Distributed Mission Operations Baseline

## 1. Document Control & Purpose
* **System Baseline:** Version 1.3.0 (Hub-and-Spoke Dynamic Manifest Registry)
* **Status:** Active Configuration
* **Description:** This document serves as the master interface contract between all core nodes, platform utilities, and micro-frontend shells within the repository. It freezes network paths, schema contracts, and error codes to allow decoupled subsystem development. All frontend remote discovery concerns are abstracted via a centralized Hub-and-Spoke runtime registry utilizing asynchronous `mf-manifest.json` endpoint streams, eliminating static file-sharing dependencies.

---

## 2. Global Network & Observability Parameters
* **Primary Ingress Gateways:**
  - **Decentralized Local Dev (Compose):** `http://localhost` (Managed by Traefik container routing proxy)
  - **Integrated Kubernetes (k3d):** `http://localhost:8081` (Managed by Traefik ingress controller)
* **Federation Manifest Discovery Endpoint:** `/registry/apps.json`
  - Serves as the authoritative registry lookup configuration mapping human-readable domain shell and service client keys to their respective micro-frontend manifest locations.
* **Traceability Requirement (Correlation ID):** Every transaction must carry a unique `X-Correlation-ID` header (UUIDv4) generated by the entry node to ensure complete distributed observability.

## 3. Path-Routed HTTP API Contracts (Core Verification Gate)

### 3.1. UI Application Registry Contracts (`/registry/apps.json`)
Exposes the active platform layout matrix to the global and domain hosts on boot.

* **Response Schema (200 OK):**
  ```json
  {
    "remotes": [
      {
        "type": "esm",
        "name": "topology_shell",
        "entry": "http://localhost:8081/topology-shell/mf-manifest.json"
      },
      {
        "type": "esm",
        "name": "compliance_shell",
        "entry": "http://localhost:8081/compliance-shell/mf-manifest.json"
      }
    ]
  }
  ```

## 4. Standard System Network Error States
Every service operating in the cluster network interface must respond with a uniform schema when an error gate is triggered:

```json
{
  "errorCode": "string (e.g., SCHEMA_VALIDATION_FAILURE, ACCESS_DENIED)",
  "message": "string (Human readable description)",
  "correlationId": "string (UUIDv4)",
  "timestamp": "string (ISO 8601 UTC)"
}
```
